# Motion Lab

**A deterministic motion-graphics studio for frame-accurate video.**
Motion is written as code, validated by static gates, and rendered to MP4 at 60 FPS — never generated by a black box.

## What Motion Lab is

Motion Lab is a React-based production environment for motion design. A video is
described by three files, checked by a stack of automated audits, and rendered by
Remotion with GSAP timelines.

| Stage | Artefact | Purpose |
| --- | --- | --- |
| Direction | `src/projects/<slug>/direction.md` | A short concept note. |
| Contract and storyboard | `src/projects/<slug>/spec.json` | Beat timeline, one `board` card per beat (focal element, 3x3 zone, start and end key poses, text, reason), camera keyframes, `"harness": 2`. |
| Implementation | `src/projects/<slug>/Scene.tsx` | Exports `buildTimeline`; motion is scheduled with presets and physics helpers, not hand-written tweens. |

Harness v2 (0.9.0) is designed so that mid-size models can produce good motion
without taking shortcuts. [`RULES.md`](RULES.md) is the single canonical rule file,
motion comes from a closed preset vocabulary, and the audits check behavior (what
the timeline does, what is on screen) rather than keywords. Projects opt in with
`"harness": 2` in `spec.json`; legacy projects keep working under the older audits.

Every animation frame is a pure function of `frame / fps`. The same commit
produces the same pixels on every machine, at 60 FPS, in 9:16 or 16:9.

**Core stack:** React 19, Remotion 4, GSAP 3, TypeScript, Vite, Tailwind CSS 4.

## What it is not

- **Not a text-to-video model.** There is no prompt-to-pixels step. Every visual
  is a component you can read, diff, and review.
- **Not a slide-deck exporter.** Scenes are continuous stages, not crossfaded
  slides.
- **Not a dashboard mockup kit.** Consumer and brand videos use authentic product
  anatomy, not invented server telemetry.
- **Not a hosted service.** It runs locally, with no API keys and no external
  accounts. Web search is never required.

## Design constraints

These are enforced by the audits in [`scripts/`](scripts), not just documented.
The full list of codes is in [`RULES.md`](RULES.md).

| Rule | Enforcement |
| --- | --- |
| Animate only `transform`, `opacity`, `filter` | `audit:timeline` (T005) and `audit:ast` (A003) reject tweens on layout properties (`top`, `width`, `height`, margins, ...). |
| Motion comes from presets | `audit:ast` (V2-004) rejects direct `gsap.*` calls; `audit:timeline` (T006) warns when under 60% of tweens use presets. |
| Deterministic timelines only | Scenes export `buildTimeline` and call `useRemotionGSAP(buildTimeline)`. `Math.random`, `Date.now`, timers and CSS transitions are rejected (A004, A005), as are animating in React (V2-005) and sniffing the environment (V2-006). |
| Every beat has a storyboard card | `audit:storyboard2` (SB001-SB007): focal element, zone, key poses, reading time, final-hold text. |
| The timeline does what the brief says | `audit:timeline` (T000-T014): beat labels, dead beats, selector reality, speed, easing direction, rhythm, the 1.2 s final hold. |
| The real page shows it | `pnpm probe` (P001-P009) renders the scene in headless Chrome and checks visibility, contrast, text size and the closing hold. |
| No micro-type, emoji or fake telemetry | `audit:slop` and the probe enforce text of 18 px or larger, no system emoji, no neon palettes. |
| No `Scene.tsx` / `spec.json` drift | `audit:spec` cross-checks beats, camera keys, and scene code. |
| No glyph or encoding surprises | `audit:glyph` validates Turkish and international typography. |

Legacy projects (no `"harness": 2`) are checked by the older keyword audits
(`audit:craft`, `audit:critic`, `audit:motion`, `audit:storyboard`); v2 projects
skip those and are checked by the behavior audits above.

## Architecture

Motion Lab separates **engine**, **vocabulary**, and **content**:

```
src/
  core/          Deterministic bridge (useRemotionGSAP), tokens, recipes, math, audio,
                 presets.ts (motion vocabulary), physics.ts (bounce, arcs, walk, rig helpers)
  primitives/    curated.ts (the only primitives v2 scenes import), characters/RigCharacter,
                 plus legacy primitives (deprecated, kept for older projects)
  projects/      One isolated project per video: example-* (golden), study-* (animation
                 studies), zz-gallery, and legacy projects
  world/ vfx/ archetypes/ templates/   Legacy stage, particles, archetype cards, 23 template kits
  remotion/      Composition entry point and registry
  stage/ camera/ motion/ materials/ procedural/   Supporting layers

evals/           Graded tasks, reference solutions, visual rubric, integrity lock
docs/            Teaching docs, generated docs, gallery thumbnails
.agent/skills/   6 maintained skills (legacy ones live in .agent/skills-archive/)
scripts/         CLI, audits, browser probe, renderer, eval scorer, asset harvesters
references/      Storyboard rules, typography guide, measured/ timing statistics,
                 prompts/, broll-examples/ (legacy guides in references/archive/)
public/          Fonts, CC0 sound effects, audio beds
out/             Rendered outputs (git-ignored)
```

Flow of a v2 video: **spec boards** (`spec.json`) -> **`Scene.tsx` `buildTimeline`**
-> **presets / physics** (`src/core`) -> **audits** (`pnpm check`) -> **browser probe**
(`pnpm probe`) -> **render** (`pnpm render`). The engine layer is intentionally small.
Content lives in projects; reusable behaviour lives in curated primitives and
`src/core`. A project never forks the engine. Details:
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Quick start

### 1. Render an existing project

```bash
pnpm render --project example-kinetic-type
```

Output: `out/example-kinetic-type/example-kinetic-type.mp4`.

### 2. Create a new video (harness v2)

```bash
pnpm new my-product --mode editorial-ui --aspect 9:16 --duration 12
```

This scaffolds a v2 project (`"harness": 2`) with a `board` per beat in
`spec.json`, a short `direction.md`, and a `Scene.tsx` that passes `pnpm check`
without edits, then updates the generated project registry. `--legacy` scaffolds
the old layout. `--mode cinematic-world` scaffolds a `RigCharacter` scene.

### 3. Storyboard, poses, then motion

1. Read [`RULES.md`](RULES.md), then [`docs/STORYBOARD.md`](docs/STORYBOARD.md); write a `board` for every beat in `spec.json`.
2. Build the static layout in `Scene.tsx`, copying the closest `example-*` project.
3. Run `pnpm render:poses --project my-product`, open `out/my-product/poses/poses-grid.png`, and fix the layout against each board.
4. Only then add motion, picking presets from [`docs/PRESETS.md`](docs/PRESETS.md).
5. Run `pnpm check --project my-product` until there are no errors, then
   `pnpm render:contact-sheet --project my-product` and review `out/my-product/visual-audit-grid.png`.
6. Run `pnpm render --project my-product`.

### 4. Open the interactive preview

```bash
pnpm studio:preview
```

### Useful commands

| Command | What it does |
| --- | --- |
| `pnpm check [--project <slug>]` | Full quality gate: audits, unit tests, generated-doc freshness, `tsc --noEmit`. |
| `pnpm render:poses --project <slug>` | Key-pose stills at the start and end of every beat, plus `poses-grid.png`. |
| `pnpm render:contact-sheet --project <slug>` | `out/<slug>/visual-audit-grid.png` from the beat boundaries. |
| `pnpm probe --project <slug>` | Headless-Chrome check of what the scene really shows (P001-P009). |
| `pnpm eval:score --task <id> --project <slug>` | Grades a project against an eval task, 0-100. |
| `pnpm doctor [--project <slug>]` | 14-point repository health audit (legacy heuristics). |
| `pnpm gate --project <slug>` | Pre-render checklist for one project. |
| `pnpm inspect <slug> --t <seconds>` | Renders and inspects a single frame. |
| `pnpm studio:brief <slug> --topic "..." --goal "..."` | Generates a 7-part director brief (legacy workflow). |
| `pnpm music:map <audio-file>` | Builds a beat map from an audio track. |

Every script in `package.json` is documented in [`docs/CLI_REFERENCE.md`](docs/CLI_REFERENCE.md).

## The four orchestration modes

| Mode | Use for | Signature |
| --- | --- | --- |
| `editorial-ui` | SaaS, fintech, product demos | App shells, hairline grids, charts, camera moves over a virtual canvas. |
| `cinematic-world` | Characters, narrative | A `RigCharacter` scene: `rigWalk`, `lookAt`, `react`. |
| `kinetic-poster` | Ads, manifestos, social drops | Full-bleed typography, masked splits, beat-locked cuts. |
| `hybrid-orchestrated` | Multi-archetype stories | One hero element carried across sections without a cut. |

Agents plan and build scenes with [`.agent/skills/motion-playbook`](.agent/skills/motion-playbook/SKILL.md).

## Quality gates

`pnpm check` is the single entry point. It refreshes the project registry, then
runs the audits below, the unit and fixture tests, the generated-doc freshness
checks and `tsc --noEmit`. Fix every error; warnings are advice.

| Audit | Command | Applies to | Checks |
| --- | --- | --- | --- |
| Spec | `pnpm audit:spec` | all | S0xx: fps 60, duration, safe zones, beat continuity, camera keyframes. |
| Storyboard (v2) | `pnpm audit:storyboard2` | v2 | SB001-SB007: a board per beat, focal element exists in the JSX, reading time, final-hold text. |
| Storyboard (legacy) | `pnpm audit:storyboard` | legacy | Beat tables against the old storyboard constitution. |
| AST | `pnpm audit:ast` | all (V2 rules for v2) | V2-0xx import allowlist, no direct `gsap.*`, no React animation, no environment sniffing, component limits; A0xx durations, eases, determinism. |
| Timeline | `pnpm audit:timeline` | v2 | T000-T014: runs `buildTimeline` and checks beat labels, dead beats, 1.2 s hold, selector reality, speed, easing, rhythm. |
| Motion | `pnpm audit:motion` | legacy | Dead holds and beat unmounting. |
| Slop | `pnpm audit:slop` | all | Neon palettes, micro-type, emoji, fake telemetry. |
| Craft | `pnpm audit:craft` | legacy | Spring physics, CSS 3D/SVG purity, stage anchoring. |
| Visual | `pnpm audit:visual` | all | Blank frames and frame evidence. |
| Critic | `pnpm audit:critic` | legacy | Readability holds, anticipation, P0/P1/P2 triage. |
| Glyph | `pnpm audit:glyph` | all | Character encoding and typographic safety. |
| Templates | `pnpm audit:templates` | repo | Template catalog integrity. |
| Browser probe | `pnpm probe --project <slug>` | v2 | P001-P009 in real headless Chrome. Not part of `pnpm check`; run it directly, with `CHECK_PROBE=1 pnpm check`, or via `pnpm eval:score`. |
| Evals | `pnpm eval:score --task <id> --project <slug>` | v2 | 0-100 grade from the audits plus a rubric; see [`evals/README.md`](evals/README.md). |
| Doctor | `pnpm audit:doctor` | repo | 14-point repository health diagnostic. |

Environment flags for `pnpm check`: `CHECK_FAST=1` skips the eval anti-cheat
fixtures (about a minute); `CHECK_PROBE=1` adds the browser-probe fixture tests
(they need Chrome). A render is expected to pass the gate with 0 errors. Passing
the TypeScript compiler is not sufficient, and passing a linter is not approval.

## Templates, references, and skills

### Templates — `src/templates/` (23, legacy)

Declarative kits for common formats: Swiss grids, data rollups, kinetic
typography, product promos, light leaks, logo outros, and more. Each template
records its engine version, supported aspects, and upstream attribution in
`template.html-video.yaml`. They are not part of the v2 workflow.

### References — `references/`

- [`MASTER_STORYBOARD_RULES.md`](references/MASTER_STORYBOARD_RULES.md) — storyboard laws and the 3-layer depth system.
- [`TYPOGRAPHY_GUIDE.md`](references/TYPOGRAPHY_GUIDE.md) — bundled font families and readability rules.
- [`measured/`](references/measured/README.md) — timing statistics (numbers only) measured from short reference clips; they calibrate the presets.
- [`prompts/`](references/prompts/) — seven production prompt archetypes.
- [`broll-examples/`](references/broll-examples/) — six HTML B-roll interactions.
- [`archive/`](references/archive/README.md) — legacy style guides (not maintained, not for v2).

### Skills — `.agent/skills/` (6)

Six maintained skills: `motion-playbook` (start here), `kinetic-type`,
`product-ui-motion`, `character-animation`, `sound-design` and `asset-harvester`.
They are validated by `scripts/audit-skills.mjs` during `pnpm check`. Earlier
skills are archived in [`.agent/skills-archive/`](.agent/skills-archive/README.md)
and are not read by any script.

## Versioning and releases

Motion Lab follows [Semantic Versioning](https://semver.org/). The current line
is **0.9.1**, published as a **pre-release**.

- `0.9.x` — fixes only; render output is expected to be stable within the line.
- `0.x.0` — may introduce breaking changes to schemas, APIs, or CLI flags.
- `1.0.0` — first stable release.

Release notes live in [`CHANGELOG.md`](CHANGELOG.md). Git tags use the `v`
prefix (`v0.9.1`).

## Contributing

1. Branch from `main` using `feat/`, `scene/`, `fix/`, `docs/`, or `chore/`.
2. Follow Conventional Commits.
3. Run `pnpm check --project <slug>` for a project, or `pnpm check` for engine changes, and `pnpm audit:doctor`.
4. Open a pull request and complete the template checklist.
5. PRs are merged with **Squash and Merge**.

Protected harness files (`scripts/`, `src/core`, `src/primitives`, `evals/`,
`docs/`, `RULES.md`, ...) are covered by an integrity lock; see
[`CONTRIBUTING.md`](CONTRIBUTING.md) for when a change needs `pnpm eval:lock`
(maintainers only).
